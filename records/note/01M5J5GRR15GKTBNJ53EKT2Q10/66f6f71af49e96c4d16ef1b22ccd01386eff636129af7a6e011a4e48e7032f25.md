## Hvordan evaluerer vi brugen af AI

Det er ikke et spørgsmål om, vi bruger AI eller ej.

Metrikker bliver dårlige målenheder på grund af lov. Et open source-projekt er et eksempel på manglende korrelation mellem spørgsmål og effekt.

Kan vi måle forskellen mellem lokale modeller og Claude?

BPF-tidsregistreringen kan godt udvides til en anden gruppe.

Projektbudgetter vs. vedligehold: er scope det samme? Det er de gamle projekter, der er mindst vedligeholdbare.

## Hvad er næste skridt i udbredelsen

Det er ikke slået igennem i vores processer endnu. Flow af tickets.

Code reviews: hvordan håndterer vi det? En agent i GitHub med en code review-skill giver hurtigere code reviews og højere kvalitet i codebaser, man ikke kender så godt. AI-kode review på egne ting. DE-teamet laver code review på egne ting. Hvordan deklarerer vi, hvad der skal reviewes? Ved man selv, hvad der skal reviewes?

Hvordan bruger vi AI i onboarding? Der er stor spredning i erfaringen. Der er en omkostning ved at få erfaringer med nye måder at arbejde på.

Smerten ved at skrive dokumentation er blevet meget mindre. Mere dokumentation kan blive spild, fordi man er mindre hands-on. Omvendt: hvordan kan vi få noget effektivitet ud af det? Videndeling, men mere hands-on, så man har noget, der virker.

Et tværfagligt forum har lavet platformen. Skal der være et tværfagligt forum, der kan lave noget tooling? Skal vi have noget rigtig tid til at skabe AI-tooling?

Hvordan løfter vi abstraktionsniveauet?

Retninger 1-2 år frem: integration mod egne systemer, en agent der kender DBC-biblioteket, og feedback loops med read only-adgang til clusteret eller DB. Git-integration har vi ikke løst. Hvordan får vi åbnet op til nogle systemer?
